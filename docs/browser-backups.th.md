สคริปต์เหล่านี้เก็บรักษา **บอร์ด Speed Dial** ได้แก่ ลิงก์ตามลำดับ ชื่อเรื่อง ไบต์ของภาพทั้งหมด แถว คอลัมน์ ค่ากำหนดการเปิด และภาษา ไม่ได้สำรองประวัติเบราว์เซอร์ รหัสผ่าน ส่วนขยาย หรือบุ๊กมาร์กอื่นที่ไม่เกี่ยวข้อง โดยใช้รูปแบบ JSON ที่ย้ายได้ของแอปคือ `speedial-local-backup` ไม่ใช่ฐานข้อมูลภายในของ Chrome หรือ Firefox

สคริปต์ทำงานกับแอปที่เก็บข้อมูลในเบราว์เซอร์ที่ [speeddial.alvit.here.now](https://speeddial.alvit.here.now/) และไม่ใช้แทน[การสำรองข้อมูลเซิร์ฟเวอร์](../wiki/Operations.md#backup-and-restore) สำหรับการติดตั้งด้วย Node.js, Docker หรือ k3s ไฟล์ส่งออก JSON แบบเก่าของเซิร์ฟเวอร์ไม่ถือเป็นข้อมูลสำรองเบราว์เซอร์ที่ครบถ้วน การย้ายบอร์ดนั้นต้องใช้[ขั้นตอนรวบรวมและแปลงภาพ](browser-migration.md)

หากบอร์ดยังอยู่ที่ที่อยู่เดิม `speedial.alvit.here.now` ให้ส่งออกจากที่อยู่นั้นโดยตรงก่อน เพราะสคริปต์เหล่านี้เปิด `speeddial.alvit.here.now` แล้ว ใช้ `--no-open` ร่วมกับแท็บเก่าที่เปิดไว้ หรือระบุเก็บไฟล์ส่งออกที่บันทึกไว้โดยตรง ยังรองรับไฟล์ `speedial-local-backup` เก่าและชื่อดาวน์โหลด `speedial-backup-*.json` ดู[หมายเหตุการย้ายที่อยู่](local-speedial.md#corrected-address-and-existing-backups)

## ข้อกำหนดและการรองรับเบราว์เซอร์

เรียกใช้ Node.js 24+ จากสำเนา Git ที่เช็กเอาต์นี้ ไม่ต้องติดตั้งแพ็กเกจเพิ่ม บน macOS ตัวเปิดโปรแกรมตรวจพบ Chrome, Firefox, Safari, Edge, Brave, Arc, Opera, Vivaldi, Chromium, Orion, Zen, LibreWolf และ Waterfox ใน `/Applications`, `~/Applications` หรือ `/System/Applications` นี่คือการรองรับของตัวเปิดโปรแกรม ไม่ใช่การอ้างว่าทดสอบเบราว์เซอร์ทุกรายการแล้ว การทดสอบแอปอัตโนมัติใช้ Chromium, Firefox และ WebKit

```sh
npm run backup:browser -- --list-browsers
```

สำหรับเบราว์เซอร์ macOS อื่น ให้ใช้ `--app /absolute/path/Browser.app` สำหรับเบราว์เซอร์ที่เปิดไว้แล้ว เบราว์เซอร์ภายใน Codex, Windows หรือ Linux ให้ใช้ `--no-open` และเปิดเว็บไซต์เอง ไม่ต้องใช้พอร์ตดีบัก ส่วนขยาย สิทธิ์ Accessibility หรือการเข้าถึงไฟล์โปรไฟล์โดยตรง

```sh
npm run backup:browser -- --no-open
npm run restore:browser -- backups/YOUR-BACKUP.json --no-open
npm run restore:browser -- backups/YOUR-BACKUP.json --app "/Applications/Brave Browser.app"
```

URL ที่ใช้เปิดถูกกำหนดตายตัวเป็นที่อยู่หลัก บอร์ดที่อยู่ใน origin อื่นต้องส่งออกจาก origin นั้นโดยตรง ใช้ `--no-open` เมื่อทำงานที่นั่น และตรวจที่อยู่ปลายทางที่ต้องการด้วยตนเอง ที่เก็บข้อมูลของเบราว์เซอร์ไม่ย้ายตามการเปลี่ยนเส้นทางหรือชื่อโฮสต์

**สคริปต์เหล่านี้ต้องมีการโต้ตอบกับผู้ใช้** สคริปต์เปิดแอปและจัดการไฟล์ในเครื่อง แต่คุณต้องคลิกส่งออก เลือกไฟล์นำเข้า และยืนยันการแทนที่เอง แอปหนึ่งอาจมีหลายโปรไฟล์ ให้เลือกโปรไฟล์ที่ต้องการและใช้ [speeddial.alvit.here.now](https://speeddial.alvit.here.now/) โปรไฟล์ใหม่ว่างเปล่าเป็นเรื่องปกติ สคริปต์ไม่สามารถรับรองว่าโปรไฟล์ใดสร้างไฟล์ดาวน์โหลด

## สำรองข้อมูล Chrome

```sh
npm run backup:browser -- --browser chrome
```

1. เลือกโปรไฟล์ Chrome ที่มีอยู่ ขยายลูกศรมุมขวาบน แล้วคลิก **Export backup**
2. บันทึกด้วยชื่อที่แนะนำ `speedial-backup-YYYY-MM-DD.json` ใน `~/Downloads` รองรับส่วนต่อท้ายเมื่อชื่อซ้ำ เช่น ` (1)`
3. สคริปต์รอไฟล์ส่งออกใหม่ที่สมบูรณ์ ตรวจสอบความถูกต้อง คัดลอกไปยัง `backups/` อ่านสำเนากลับมา แล้วแสดงพาธ จำนวน และ SHA-256 สคริปต์จะไม่ใช้ไฟล์ส่งออกเก่าแทน หากมีหลายไฟล์ส่งออกพร้อมกันจะเกิดข้อผิดพลาดแทนการเดา

ใช้ `--downloads /absolute/local/folder` หากเบราว์เซอร์ดาวน์โหลดไว้ที่อื่น และเลือกโฟลเดอร์เดียวกันในเบราว์เซอร์ เลือกโฟลเดอร์ในเครื่องที่อยู่นอกไดเรกทอรีซิงก์คลาวด์ ค่าเริ่มต้นรอสิบนาที ส่วน `--timeout 1200` เปลี่ยนเป็นยี่สิบนาที อาจต้องยืนยันกล่องโต้ตอบ **Save As** ของเบราว์เซอร์ก่อนจึงจะมีไฟล์ สำหรับไฟล์ส่งออกที่เปลี่ยนชื่อหรือดาวน์โหลดไว้แล้ว:

```sh
npm run backup:browser -- --file /absolute/local/export.json
```

โหมดระบุไฟล์โดยตรงจะเก็บไฟล์นั้น ไม่ได้ดึงข้อมูลปัจจุบันจากเบราว์เซอร์หรือยืนยันว่าข้อมูลใหม่ ดาวน์โหลดต้นฉบับยังคงอยู่ ไฟล์ส่งออกที่ตัวเฝ้าดูรวบรวมจะจำกัดสิทธิ์เป็น `0600` บน POSIX ส่วนไฟล์อินพุตที่ระบุโดยตรงจะไม่ถูกเปลี่ยนแปลง

## กู้คืนไปยังเบราว์เซอร์อื่น

แทนที่ `YOUR-BACKUP.json` ด้วยชื่อไฟล์สำรองที่แสดง:

```sh
npm run restore:browser -- backups/YOUR-BACKUP.json --browser firefox
npm run restore:browser -- backups/YOUR-BACKUP.json --browser chrome
npm run restore:browser -- backups/YOUR-BACKUP.json --browser safari
```

คำสั่งกู้คืนต้องใช้เทอร์มินัลแบบโต้ตอบ และแนะนำขั้นตอนสำหรับเบราว์เซอร์/โปรไฟล์ครั้งละหนึ่งรายการ:

1. คำสั่งตรวจสอบและเก็บสำเนา `restore-source` แยกไว้ ในโปรไฟล์ปลายทาง ให้ส่งออกบอร์ดปัจจุบันแม้จะว่าง สคริปต์บันทึกเป็น `before-restore` เพื่อให้ยังกู้บอร์ดนั้นคืนได้
2. ยืนยันในเทอร์มินัลว่าไฟล์ส่งออกมาจากโปรไฟล์ปลายทางที่ถูกต้องโดยพิมพ์ `RESTORE`
3. คลิก **Import backup** ในเบราว์เซอร์เดียวกัน เลือกไฟล์ `restore-source` ที่แสดง ตรวจสรุป แล้วคลิก **Replace this board** บน macOS ให้กด **⌘⇧G** ในหน้าต่างเลือกไฟล์แล้ววางพาธแบบสัมบูรณ์ของไฟล์
4. โหลด Speed Dial ใหม่ ตรวจว่าภาพแสดง แล้วส่งออกอีกครั้ง สคริปต์เก็บไฟล์ส่งออก `after-restore` นี้และเปรียบเทียบลิงก์ตามลำดับ ชื่อเรื่อง ไบต์ภาพ ตาราง ค่ากำหนดการเปิด และภาษากับต้นทาง โดยไม่สนใจ ID ภายในและเวลาที่สร้างขึ้นใหม่ ข้อมูลสำรองเก่าที่ไม่มีภาษาจะไม่เปลี่ยนภาษาปลายทาง

จะรายงานความสำเร็จก็ต่อเมื่อเนื้อหาตรงกันเท่านั้น เนื้อหาไม่ตรงหรือหมดเวลา **ไม่ถือเป็น** การกู้คืนที่ยืนยันแล้ว เก็บสำเนาทั้งหมดไว้และไม่มีการย้อนกลับอัตโนมัติ หากต้องการย้อนกลับ ให้เรียกคำสั่งซ้ำด้วยไฟล์ `before-restore` ที่บันทึกไว้ ไฟล์ส่งออกที่ตรงกันพิสูจน์ว่าเนื้อหาเท่ากัน แต่ยังต้องตรวจโปรไฟล์ origin และภาพที่มองเห็น

หากต้องการกลับไป Chrome ในภายหลัง ให้ใช้คำสั่งกู้คืนเดียวกันพร้อม `--browser chrome` และไฟล์ JSON ที่บันทึกไว้ตามต้องการ รูปแบบไม่ขึ้นกับเบราว์เซอร์ต้นทาง การกู้คืนแต่ละครั้งแทนที่บอร์ดปลายทางหนึ่งบอร์ด ไม่ได้รวมลิงก์เข้าด้วยกัน หากอาจต้องใช้ทั้งสองรุ่น ให้เก็บสำเนาปลายทางที่บันทึกให้อัตโนมัติไว้

อย่าส่งออกจากแท็บหรือโปรไฟล์อื่นขณะที่คำสั่งกำลังรอ ใช้คำสั่งแยกกันสำหรับแต่ละเบราว์เซอร์ นี่คือการย้ายครั้งเดียว การแก้ไขในภายหลังจะไม่ซิงก์กัน

## การเก็บเฉพาะในเครื่องและการตรวจสอบ

เอาต์พุตทั้งหมดของสคริปต์อยู่ในไดเรกทอรีตายตัว `backups/` ของสำเนาที่เช็กเอาต์นี้ คำสั่งตรวจว่า Git ละเว้นไดเรกทอรีนี้และไม่มีไฟล์ที่ติดตามอยู่ ปฏิเสธไดเรกทอรีเอาต์พุตที่เป็น symlink ข้อมูลสำรองแต่ละชุดมีชื่อไม่ซ้ำ บันทึกโดยไม่เขียนทับไฟล์อื่น อ่านกลับ และมี `.receipt.json` ที่บันทึกจำนวนกับไดเจสต์ แต่ไม่มีชื่อเรื่องหรือ URL อินพุตไม่ถูกต้องจะไม่สร้างข้อมูลสำรอง CLI ใช้การตรวจ schema, base64 และส่วนหัวภาพแรสเตอร์ของแอปร่วมกัน ส่วนแอปปลายทางยังถอดรหัสภาพก่อนนำเข้าแบบอะตอมด้วย

ใช้ไฟล์ `.json` ของบอร์ดในการกู้คืน ไม่ใช่ไฟล์ `.receipt.json` ที่อยู่คู่กัน ใบรับบันทึกเมทาดาทาการตรวจสอบและไม่สามารถกู้บอร์ดได้ สคริปต์ไม่ลบข้อมูลสำรองเก่าหรือดาวน์โหลดต้นฉบับโดยอัตโนมัติ ให้เก็บสำเนาที่ต้องการและจัดการพื้นที่จัดเก็บในเครื่องเอง

บน macOS/Linux ไดเรกทอรีมีโหมด `0700` และไฟล์มีโหมด `0600` บน Windows ให้จำกัดการเข้าถึงด้วย ACL ของระบบไฟล์สำหรับบัญชี โหมด POSIX ไม่รับประกัน ACL ข้อมูลสำรอง JSON เป็นข้อความธรรมดา สคริปต์ไม่มีโค้ดอัปโหลดหรือซิงก์ โฟลเดอร์ถูกยกเว้นจาก Git อินพุตการสร้าง Docker และรายการอนุญาตของฟรอนต์เอนด์สาธารณะ `.gitignore` ไม่ได้ป้องกันการบังคับเพิ่มเข้า Git การแชร์ด้วยตนเอง การสำรองข้อมูลของ OS หรือไคลเอนต์ซิงก์ที่ตั้งค่าแยกไว้ หากต้องการเก็บเฉพาะในเครื่อง ให้วางสำเนาที่เช็กเอาต์และโฟลเดอร์ดาวน์โหลดนอกไดเรกทอรีที่ซิงก์

ไม่มีข้อมูลบอร์ดฝังในสคริปต์ การทดสอบ เอกสาร หรือเว็บไซต์สาธารณะ ดู[ข้อจำกัดของที่เก็บข้อมูลเบราว์เซอร์](local-speedial.md#what-is-private-and-what-is-not)และ[เกณฑ์ตรวจรับการย้าย](browser-migration.md)
