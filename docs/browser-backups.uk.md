Скрипти зберігають **панель Speed Dial**: порядок посилань, назви, повні байти зображень, рядки, стовпці, спосіб відкриття та мову. Вони не копіюють історію браузера, паролі, розширення чи сторонні закладки. Використовується переносний JSON-формат застосунку `speedial-local-backup`, а не внутрішні бази Chrome або Firefox.

Вони працюють із локальним браузерним застосунком на [speeddial.alvit.here.now](https://speeddial.alvit.here.now/). Вони не замінюють [серверні резервні копії](../wiki/Operations.md#backup-and-restore) для Node.js, Docker чи k3s. Старий JSON-експорт сервера не приймається як повна браузерна копія; перенесення такої панелі потребує [збирання та перетворення зображень](browser-migration.md).

Якщо панель досі за адресою `speedial.alvit.here.now`, спершу експортуйте саме звідти: тепер скрипти відкривають `speeddial.alvit.here.now`. Використовуйте `--no-open` з уже відкритою старою вкладкою або явно архівуйте збережений експорт. Старі файли `speedial-local-backup` і назви завантажень `speedial-backup-*.json` підтримуються. Див. [пояснення зміни адреси](local-speedial.md#corrected-address-and-existing-backups).

## Вимоги та підтримка браузерів

Запускайте Node.js 24+ із цієї робочої копії Git. Додаткові пакети не потрібні. На macOS засіб запуску розпізнає Chrome, Firefox, Safari, Edge, Brave, Arc, Opera, Vivaldi, Chromium, Orion, Zen, LibreWolf і Waterfox у `/Applications`, `~/Applications` або `/System/Applications`. Це підтримка запуску, а не твердження про перевірку кожного браузера. Автоматичні тести застосунку використовують Chromium, Firefox і WebKit.

```sh
npm run backup:browser -- --list-browsers
```

Для іншого браузера macOS використовуйте `--app /absolute/path/Browser.app`. Для вже відкритого браузера, вбудованого браузера Codex, Windows або Linux використовуйте `--no-open` і відкрийте сайт самостійно. Порт налагодження, розширення, дозвіл Accessibility і прямий доступ до файлів профілю не потрібні.

```sh
npm run backup:browser -- --no-open
npm run restore:browser -- backups/YOUR-BACKUP.json --no-open
npm run restore:browser -- backups/YOUR-BACKUP.json --app "/Applications/Brave Browser.app"
```

URL запуску закріплено за основною адресою. Панель з іншого origin потрібно експортувати саме звідти; використовуйте там `--no-open` і самостійно перевіряйте адресу призначення. Сховище браузера не переноситься через перенаправлення чи зміну імені хоста.

**Скрипти інтерактивні.** Вони відкривають застосунок і керують локальними файлами, але експорт, вибір імпортованого файлу й підтвердження заміни виконуєте ви. Застосунок може мати кілька профілів: виберіть потрібний і використовуйте [speeddial.alvit.here.now](https://speeddial.alvit.here.now/). Порожня панель нового профілю очікувана. Скрипт не може засвідчити, який профіль створив завантаження.

## Резервне копіювання з Chrome

```sh
npm run backup:browser -- --browser chrome
```

1. Виберіть наявний профіль Chrome, розгорніть стрілку справа вгорі й натисніть **Export backup**.
2. Збережіть із запропонованою назвою `speedial-backup-YYYY-MM-DD.json` у `~/Downloads`. Суфікси однакових назв, як-от ` (1)`, підтримуються.
3. Скрипт чекає нового завершеного експорту, перевіряє його, копіює до `backups/`, перечитує копію та виводить шлях, кількості й SHA-256. Він ніколи не підставляє старий експорт. Кілька одночасних експортів викликають помилку замість вгадування.

Якщо браузер завантажує в інше місце, використовуйте `--downloads /absolute/local/folder` і виберіть ту саму папку в браузері. Вибирайте локальні папки поза хмарною синхронізацією. Типове очікування — десять хвилин; `--timeout 1200` збільшує його до двадцяти. Діалог браузера **Save As** може потребувати підтвердження, перш ніж файл з'явиться. Для перейменованого або вже завантаженого експорту:

```sh
npm run backup:browser -- --file /absolute/local/export.json
```

Режим явного файлу архівує саме цей файл; він **не** отримує поточні дані браузера й не підтверджує їхню актуальність. Оригінали завантажень зберігаються. Експорти, отримані спостерігачем, мають на POSIX режим `0600`; явно задані вхідні файли не змінюються.

## Відновлення в іншому браузері

Замініть `YOUR-BACKUP.json` виведеною назвою резервної копії:

```sh
npm run restore:browser -- backups/YOUR-BACKUP.json --browser firefox
npm run restore:browser -- backups/YOUR-BACKUP.json --browser chrome
npm run restore:browser -- backups/YOUR-BACKUP.json --browser safari
```

Команда відновлення потребує інтерактивного термінала й працює з одним браузером/профілем за раз:

1. Вона перевіряє та зберігає окрему копію `restore-source`. У цільовому профілі експортуйте поточну панель, навіть порожню. Скрипт збереже її як `before-restore`, щоб її можна було відновити.
2. Підтвердьте в терміналі, що експорт походить із правильного цільового профілю, ввівши `RESTORE`.
3. У тому самому браузері натисніть **Import backup**, виберіть вказаний файл `restore-source`, перевірте підсумок і натисніть **Replace this board**. На macOS у виборі файлу натисніть **⌘⇧G** і вставте абсолютний шлях.
4. Перезавантажте Speed Dial, перевірте показ зображень і експортуйте знову. Скрипт архівує цей експорт `after-restore` та порівнює з джерелом порядок посилань, назви, байти зображень, сітку, спосіб відкриття й мову. Заново створені внутрішні ID й часові мітки ігноруються. Старі копії без мови залишають мову призначення незмінною.

Успіх повідомляється лише після збігу вмісту. Незбіг або таймаут **не** означає перевірене відновлення. Усі копії залишаються; автоматичного відкоту немає. Для відкоту повторіть команду зі збереженим файлом `before-restore`. Однакові експорти доводять рівність вмісту; профіль, origin і видимі зображення все одно потрібно перевірити.

Для подальшого повернення до Chrome використовуйте ту саму команду з `--browser chrome` і потрібним збереженим JSON. Формат не залежить від браузера-джерела. Кожне відновлення замінює одну цільову панель, а не об'єднує посилання; збережіть автоматичну копію призначення, якщо знадобляться обидві версії.

Поки команда чекає, не експортуйте з іншої вкладки чи профілю. Для різних браузерів запускайте окремі команди. Це одноразове перенесення; подальші зміни не синхронізуються.

## Лише локальне зберігання й перевірка

Усі вихідні файли скриптів потрапляють до фіксованого каталогу `backups/` цієї робочої копії. Команда перевіряє, що Git його ігнорує та що там немає відстежуваних файлів. Каталог виводу у вигляді символічного посилання відхиляється. Кожна копія має унікальну назву, записується без перезапису іншого файлу, перечитується та супроводжується `.receipt.json` із кількостями й хешами, але без назв чи URL. Некоректні вхідні дані не створюють копію. CLI повторно використовує перевірку схеми, base64 і растрових заголовків застосунку; цільовий застосунок додатково декодує зображення перед атомарним імпортом.

Для відновлення використовуйте файл панелі `.json`, а не супровідний `.receipt.json`. Квитанція містить метадані перевірки й не може відновити панель. Скрипти не видаляють старі копії чи оригінали завантажень автоматично; залишайте потрібні копії та керуйте зберіганням локально.

На macOS/Linux каталог має режим `0700`, файли — `0600`. На Windows обмежте доступ ACL файлової системи для облікового запису; режими POSIX не гарантують ACL. JSON-копії — відкритий текст. Скрипти не мають коду вивантаження чи синхронізації. Папку виключено з Git, контексту складання Docker і списку дозволених файлів публічного інтерфейсу. `.gitignore` не перешкоджає примусовому додаванню в Git, ручному поширенню, резервним копіям ОС чи окремо налаштованому клієнту синхронізації. Для суто локального зберігання тримайте робочу копію та завантаження поза синхронізованими каталогами.

Дані панелей не вбудовані у скрипти, тести, документацію чи публічний сайт. Див. [обмеження браузерного сховища](local-speedial.md#what-is-private-and-what-is-not) і [приймання міграції](browser-migration.md).
