# Локальный бэкап и восстановление Speedial

[English / полная техническая инструкция](browser-backups.md) · [Перенос существующей панели](browser-migration.md) · [Варианты запуска](../README.md#storage-and-deployment)

Скрипты сохраняют панель Speedial: ссылки и порядок, названия, байты картинок, строки и столбцы, способ открытия ссылок и язык. Пароли, история и остальные закладки браузера в копию не входят. Нужен Node.js 24+; команды запускаются из этого Git-репозитория.

Это инструменты для браузерной версии на [speedial.alvit.here.now](https://speedial.alvit.here.now/). Серверная версия по-прежнему запускается через Node.js, Docker и k3s, но требует [отдельной копии SQLite, изображений и секретов](../wiki/Operations.md#backup-and-restore). Старый JSON-экспорт сервера не содержит картинки и не принимается как полная копия браузерной панели.

## Сделать копию из Chrome

```sh
npm run backup:browser -- --browser chrome
```

В Chrome выберите нужный профиль и адрес [speedial.alvit.here.now](https://speedial.alvit.here.now/). Раскройте стрелку справа сверху, нажмите **Export backup** («Экспорт копии») и сохраните файл под предложенным именем `speedial-backup-YYYY-MM-DD.json` в `~/Downloads`. Суффиксы совпадающих имён, например ` (1)`, поддерживаются. Скрипт дождётся нового файла, проверит формат и заголовки картинок, запишет копию в `backups/`, перечитает её и покажет путь и контрольную сумму. Старые файлы он автоматически не выбирает; при нескольких новых экспортах завершится ошибкой вместо угадывания.

Для другой локальной папки загрузок добавьте `--downloads /абсолютный/путь`. Для уже скачанного файла:

```sh
npm run backup:browser -- --file /абсолютный/путь/export.json
```

В этом режиме сохраняется указанный файл, а не текущее состояние браузера. Исходники в загрузках остаются на месте. Для пойманного нового экспорта на POSIX задаются права `0600`; явно указанный входной файл не меняется. Ожидание нового экспорта — десять минут, изменить его можно через `--timeout 1200` (секунды). Если браузер показывает диалог сохранения, подтвердите его, чтобы файл появился на диске.

## Восстановить в другом браузере

Замените `YOUR-BACKUP.json` именем файла, напечатанным при сохранении. Нужен интерактивный терминал.

```sh
npm run restore:browser -- backups/YOUR-BACKUP.json --browser firefox
npm run restore:browser -- backups/YOUR-BACKUP.json --browser chrome
npm run restore:browser -- backups/YOUR-BACKUP.json --browser safari
```

1. Скрипт проверит исходную копию и сохранит отдельный файл `restore-source`. В целевом браузере экспортируйте существующую панель, даже пустую: она сохранится как `before-restore` для возможного отката.
2. Убедитесь, что экспорт сделан из нужного профиля, и введите `RESTORE` в терминале.
3. В этом же браузере нажмите **Import backup**, выберите напечатанный файл `restore-source`, проверьте сводку и нажмите **Replace this board**. В диалоге выбора файла на Mac можно нажать **⌘⇧G** и вставить полный путь.
4. Перезагрузите страницу, проверьте картинки и снова нажмите **Export backup**. Скрипт сравнит ссылки, порядок, названия, все байты картинок и настройки. Только совпадение означает успешную проверку. Старые копии без языка сохраняют текущий язык назначения.

При ошибке или таймауте все копии остаются, но успешное восстановление не подтверждено. Автоматического отката нет: для него запустите восстановление из `before-restore`. Совпадение файлов подтверждает содержимое; нужный профиль, адрес и отображение картинок проверьте самостоятельно. Не экспортируйте из других вкладок или профилей, пока скрипт ждёт файл. Каждый браузер восстанавливайте отдельно. Это перенос, а не синхронизация.

Для возврата в Chrome используется та же команда с `--browser chrome`. Формат не зависит от браузера, создавшего копию. Импорт заменяет всю панель назначения, а не объединяет списки; сохраняйте `before-restore`, если прежняя версия ещё нужна.

## Другие браузеры и приватность

```sh
npm run backup:browser -- --list-browsers
```

На macOS предусмотрены Chrome, Firefox, Safari, Edge, Brave, Arc, Opera, Vivaldi, Chromium, Orion, Zen, LibreWolf и Waterfox по стандартным путям. Для другого приложения укажите `--app /полный/путь/Browser.app`. Для уже открытого браузера, встроенного браузера Codex, Windows или Linux используйте `--no-open` и откройте сайт самостоятельно. Это поддержка запуска, а не утверждение, что каждый браузер протестирован.

```sh
npm run backup:browser -- --no-open
npm run restore:browser -- backups/YOUR-BACKUP.json --no-open
npm run restore:browser -- backups/YOUR-BACKUP.json --app "/Applications/Brave Browser.app"
```

Скрипт открывает основной адрес приложения. Если панель хранится на другом домене, экспортируйте её именно там через режим `--no-open` и самостоятельно проверьте адрес назначения. Смена домена, браузера или профиля не переносит хранилище. Скрипт не может определить профиль по скачанному файлу.

Скрипты интерактивные: экспорт, выбор файла и подтверждение импорта выполняются в браузере. Отладочные порты, расширения, разрешение Accessibility и изменение внутренних баз профиля не нужны.

У каждой копии уникальное имя и файл `.receipt.json` с количеством элементов и контрольными суммами без ссылок и названий. Для восстановления нужен основной JSON, а не receipt. Скрипт проверяет исключение `backups/` из Git, отсутствие отслеживаемых файлов и симлинка вместо папки, перечитывает записанную копию. Браузер дополнительно декодирует изображения перед атомарным импортом. Старые копии и исходники из загрузок автоматически не удаляются.

Папка `backups/` исключена из Git и Docker и не входит в публичную сборку. На macOS/Linux права папки — `0700`, файлов — `0600`; на Windows доступ регулируется ACL учётной записи. Скрипты ничего не загружают в облако. JSON не зашифрован. `.gitignore` не блокирует принудительный `git add`, ручную отправку и стороннюю синхронизацию: репозиторий и папку загрузок храните вне iCloud/Dropbox/OneDrive и подобных каталогов. Ссылки, картинки и копии не должны попадать в исходники, логи, документацию или на хостинг.
