এই স্ক্রিপ্টগুলো **Speed Dial বোর্ড** সংরক্ষণ করে: ক্রমানুসারে লিংক, শিরোনাম, ছবির সম্পূর্ণ বাইট, সারি, কলাম, খোলার পছন্দ এবং ভাষা। এগুলো ব্রাউজারের ইতিহাস, পাসওয়ার্ড, এক্সটেনশন বা সম্পর্কহীন বুকমার্কের ব্যাকআপ নেয় না। Chrome বা Firefox-এর অভ্যন্তরীণ ডেটাবেসের পরিবর্তে অ্যাপের বহনযোগ্য `speedial-local-backup` JSON বিন্যাস ব্যবহার করে।

এগুলো [speeddial.alvit.here.now](https://speeddial.alvit.here.now/)-এর ব্রাউজারে স্থানীয়ভাবে চলা অ্যাপে কাজ করে। Node.js, Docker বা k3s স্থাপনের [সার্ভার ব্যাকআপের](../wiki/Operations.md#backup-and-restore) বিকল্প নয়। সার্ভারের পুরোনো JSON এক্সপোর্ট সম্পূর্ণ ব্রাউজার ব্যাকআপ হিসেবে গ্রহণযোগ্য নয়; সেই বোর্ড স্থানান্তরে [ছবি সংগ্রহ ও রূপান্তরের পদ্ধতি](browser-migration.md) প্রয়োজন।

আপনার বোর্ড এখনও আগের `speedial.alvit.here.now` ঠিকানায় থাকলে প্রথমে ঠিক সেই ঠিকানা থেকেই এক্সপোর্ট করুন; স্ক্রিপ্টগুলো এখন `speeddial.alvit.here.now` খোলে। আগে থেকে খোলা পুরোনো ব্রাউজার ট্যাবের সঙ্গে `--no-open` ব্যবহার করুন, অথবা তার সংরক্ষিত এক্সপোর্ট স্পষ্টভাবে আর্কাইভ করুন। পুরোনো `speedial-local-backup` ফাইল এবং `speedial-backup-*.json` ডাউনলোড নাম এখনও সমর্থিত। [ঠিকানা স্থানান্তরের নোট](local-speedial.md#corrected-address-and-existing-backups) দেখুন।

## প্রয়োজনীয়তা ও ব্রাউজার সমর্থন

এই Git চেকআউট থেকে Node.js 24+ চালান। অতিরিক্ত প্যাকেজ ইনস্টল করতে হবে না। macOS-এ লঞ্চার `/Applications`, `~/Applications` বা `/System/Applications`-এর অধীনে Chrome, Firefox, Safari, Edge, Brave, Arc, Opera, Vivaldi, Chromium, Orion, Zen, LibreWolf ও Waterfox শনাক্ত করে। এটি লঞ্চারের সমর্থন; উল্লিখিত প্রতিটি ব্রাউজার পরীক্ষা করা হয়েছে এমন দাবি নয়। অ্যাপের স্বয়ংক্রিয় পরীক্ষায় Chromium, Firefox ও WebKit ব্যবহার করা হয়।

```sh
npm run backup:browser -- --list-browsers
```

অন্য macOS ব্রাউজারের জন্য `--app /absolute/path/Browser.app` ব্যবহার করুন। আগে থেকে খোলা ব্রাউজার, Codex-এর অ্যাপের ভেতরের ব্রাউজার, Windows বা Linux-এর জন্য `--no-open` ব্যবহার করে নিজে সাইট খুলুন। ডিবাগিং পোর্ট, এক্সটেনশন, Accessibility অনুমতি বা প্রোফাইল ফাইলে সরাসরি প্রবেশের প্রয়োজন নেই।

```sh
npm run backup:browser -- --no-open
npm run restore:browser -- backups/YOUR-BACKUP.json --no-open
npm run restore:browser -- backups/YOUR-BACKUP.json --app "/Applications/Brave Browser.app"
```

লঞ্চ URL মূল ঠিকানায় স্থির। অন্য origin-এ থাকা বোর্ডকে ঠিক সেই origin থেকেই এক্সপোর্ট করতে হবে; সেখানে কাজ করার সময় `--no-open` ব্যবহার করুন এবং কাঙ্ক্ষিত গন্তব্য ঠিকানা নিজে যাচাই করুন। রিডাইরেক্ট বা হোস্টনাম বদলের সঙ্গে ব্রাউজারের স্টোরেজ স্থানান্তরিত হয় না।

**এই স্ক্রিপ্টগুলো ইন্টারঅ্যাকটিভ।** এগুলো অ্যাপ খোলে এবং স্থানীয় ফাইল পরিচালনা করে, কিন্তু এক্সপোর্টে ক্লিক করা, ইম্পোর্ট ফাইল বাছা ও প্রতিস্থাপন নিশ্চিত করার কাজ আপনাকেই করতে হবে। একটি অ্যাপে একাধিক প্রোফাইল থাকতে পারে: কাঙ্ক্ষিত প্রোফাইল বেছে [speeddial.alvit.here.now](https://speeddial.alvit.here.now/) ব্যবহার করুন। নতুন প্রোফাইল ফাঁকা থাকাই স্বাভাবিক। কোন প্রোফাইল ডাউনলোডটি তৈরি করেছে তা স্ক্রিপ্ট প্রত্যয়ন করতে পারে না।

## Chrome-এর ব্যাকআপ নিন

```sh
npm run backup:browser -- --browser chrome
```

1. আপনার বিদ্যমান Chrome প্রোফাইল বেছে নিন, ওপরের ডান পাশের তীরটি প্রসারিত করুন এবং **Export backup**-এ ক্লিক করুন।
2. প্রস্তাবিত `speedial-backup-YYYY-MM-DD.json` নামে `~/Downloads`-এ সেভ করুন। নামের সংঘর্ষ এড়ানোর ` (1)`-এর মতো প্রত্যয় সমর্থিত।
3. স্ক্রিপ্ট নতুন, সম্পূর্ণ এক্সপোর্টের জন্য অপেক্ষা করে, তা যাচাই করে, `backups/`-এ কপি করে, কপিটি আবার পড়ে এবং তার পথ, গণনা ও SHA-256 দেখায়। কখনো বিকল্প হিসেবে পুরোনো এক্সপোর্ট ব্যবহার করে না। একসঙ্গে একাধিক এক্সপোর্ট এলে আন্দাজ না করে ত্রুটি জানায়।

ব্রাউজার অন্য কোথাও ডাউনলোড করলে `--downloads /absolute/local/folder` ব্যবহার করুন; ব্রাউজারেও একই ফোল্ডার বাছুন। ক্লাউড-সিঙ্ক ডিরেক্টরির বাইরে স্থানীয় ফোল্ডার বেছে নিন। সাধারণ অপেক্ষা দশ মিনিট; `--timeout 1200` তা বিশ মিনিট করে। ফাইল তৈরি হওয়ার আগে ব্রাউজারের **Save As** ডায়ালগে নিশ্চিত করতে হতে পারে। নাম বদলানো বা ইতিমধ্যে ডাউনলোড করা এক্সপোর্টের জন্য:

```sh
npm run backup:browser -- --file /absolute/local/export.json
```

নির্দিষ্ট ফাইল মোড সেই ফাইলটিই আর্কাইভ করে; এটি ব্রাউজারের বর্তমান ডেটা আনে **না**, বা তা নতুন বলে প্রমাণ করে না। মূল ডাউনলোডগুলো রাখা হয়। পর্যবেক্ষক প্রক্রিয়ায় সংগ্রহ করা এক্সপোর্ট POSIX-এ `0600` মোডে সীমিত হয়; স্পষ্টভাবে দেওয়া ইনপুট ফাইল অপরিবর্তিত থাকে।

## অন্য ব্রাউজারে পুনরুদ্ধার করুন

`YOUR-BACKUP.json`-এর জায়গায় প্রদর্শিত ব্যাকআপ ফাইলের নাম দিন:

```sh
npm run restore:browser -- backups/YOUR-BACKUP.json --browser firefox
npm run restore:browser -- backups/YOUR-BACKUP.json --browser chrome
npm run restore:browser -- backups/YOUR-BACKUP.json --browser safari
```

পুনরুদ্ধার কমান্ডের জন্য ইন্টারঅ্যাকটিভ টার্মিনাল লাগে এবং একবারে একটি ব্রাউজার/প্রোফাইলের কাজ পরিচালিত হয়:

1. এটি আলাদা `restore-source` কপি যাচাই ও সংরক্ষণ করে। গন্তব্য প্রোফাইলে বর্তমান বোর্ড ফাঁকা হলেও এক্সপোর্ট করুন। স্ক্রিপ্ট তা `before-restore` হিসেবে সেভ করে, যাতে বোর্ডটি পুনরুদ্ধারযোগ্য থাকে।
2. টার্মিনালে `RESTORE` লিখে নিশ্চিত করুন যে এক্সপোর্টটি সঠিক গন্তব্য প্রোফাইল থেকে এসেছে।
3. সেই একই ব্রাউজারে **Import backup**-এ ক্লিক করুন, প্রদর্শিত `restore-source` ফাইল বাছুন, সারাংশ দেখে **Replace this board**-এ ক্লিক করুন। macOS-এর ফাইল নির্বাচকে **⌘⇧G** চেপে ফাইলের সম্পূর্ণ পথ পেস্ট করুন।
4. Speed Dial রিলোড করুন, ছবি দেখা যাচ্ছে কি না যাচাই করে আবার এক্সপোর্ট করুন। স্ক্রিপ্ট এই `after-restore` এক্সপোর্ট আর্কাইভ করে এবং ক্রমবদ্ধ লিংক, শিরোনাম, ছবির বাইট, গ্রিড, খোলার পছন্দ ও ভাষা উৎসের সঙ্গে তুলনা করে। নতুন করে তৈরি অভ্যন্তরীণ ID ও টাইমস্ট্যাম্প উপেক্ষা করা হয়। ভাষা ছাড়া পুরোনো ব্যাকআপ গন্তব্যের ভাষা অপরিবর্তিত রাখে।

বিষয়বস্তু মিললেই কেবল সাফল্য জানানো হয়। অমিল বা সময়সীমা শেষ হওয়া যাচাইকৃত পুনরুদ্ধার **নয়**। সব কপি রাখা হয়; স্বয়ংক্রিয় রোলব্যাক নেই। আগের অবস্থায় ফিরতে সংরক্ষিত `before-restore` ফাইল দিয়ে কমান্ডটি আবার চালান। এক্সপোর্টের মিল বিষয়বস্তুর সমতা প্রমাণ করে; প্রোফাইল, origin ও দৃশ্যমান ছবি যাচাই করা তবু প্রয়োজন।

পরে Chrome-এ ফিরতে একই পুনরুদ্ধার কমান্ডে `--browser chrome` ও কাঙ্ক্ষিত সংরক্ষিত JSON ফাইল ব্যবহার করুন। বিন্যাসটি উৎস ব্রাউজারের ওপর নির্ভরশীল নয়। প্রতিটি পুনরুদ্ধার গন্তব্যের একটি বোর্ড প্রতিস্থাপন করে, তার লিংক একত্র করে না; দুই সংস্করণই লাগতে পারে মনে হলে স্বয়ংক্রিয়ভাবে সংরক্ষিত গন্তব্য কপিটি রাখুন।

কমান্ড অপেক্ষা করার সময় অন্য ট্যাব বা প্রোফাইল থেকে এক্সপোর্ট করবেন না। আলাদা ব্রাউজারের জন্য আলাদা কমান্ড চালান। এটি একবারের স্থানান্তর; পরের সম্পাদনা সিঙ্ক হয় না।

## শুধু স্থানীয় সংরক্ষণ ও যাচাই

সব স্ক্রিপ্টের আউটপুট এই চেকআউটের নির্দিষ্ট `backups/` ডিরেক্টরিতে যায়। কমান্ড যাচাই করে যে Git সেটি উপেক্ষা করে এবং তাতে ট্র্যাক করা ফাইল নেই। আউটপুট ডিরেক্টরি সিমলিংক হলে তা প্রত্যাখ্যাত হয়। প্রতিটি ব্যাকআপের নাম অনন্য, অন্য ফাইল মুছে না লিখে সংরক্ষিত হয়, আবার পড়া হয় এবং গণনা ও ডাইজেস্টসহ `.receipt.json` থাকে, তবে শিরোনাম বা URL থাকে না। অবৈধ ইনপুট ব্যাকআপ তৈরি করে না। CLI অ্যাপের স্কিমা, base64 ও রাস্টার হেডার যাচাই পুনর্ব্যবহার করে; গন্তব্য অ্যাপ তার অবিভাজ্য ইম্পোর্টের আগে ছবিও ডিকোড করে।

পুনরুদ্ধারে বোর্ডের `.json` ফাইল ব্যবহার করুন, সঙ্গের `.receipt.json` নয়। রসিদে যাচাইয়ের মেটাডেটা থাকে; তা দিয়ে বোর্ড পুনরুদ্ধার হয় না। স্ক্রিপ্ট পুরোনো ব্যাকআপ বা মূল ডাউনলোড স্বয়ংক্রিয়ভাবে মুছে না; দরকারি কপি রাখুন এবং সেগুলোর স্টোরেজ স্থানীয়ভাবে পরিচালনা করুন।

macOS/Linux-এ ডিরেক্টরির মোড `0700` এবং ফাইলের `0600`। Windows-এ অ্যাকাউন্টের ফাইলসিস্টেম ACL দিয়ে প্রবেশাধিকার সীমিত করুন; POSIX মোড ACL-এর নিশ্চয়তা নয়। JSON ব্যাকআপ সাধারণ পাঠ্য। স্ক্রিপ্টে আপলোড বা সিঙ্কের কোড নেই। ফোল্ডারটি Git, Docker বিল্ডের ইনপুট ও পাবলিক ফ্রন্টএন্ডের অনুমোদিত তালিকা থেকে বাদ দেওয়া। `.gitignore` জোর করে Git-এ যোগ, হাতে শেয়ার, OS ব্যাকআপ বা আলাদাভাবে কনফিগার করা সিঙ্ক ক্লায়েন্ট ঠেকায় না। শুধু স্থানীয় সংরক্ষণের জন্য চেকআউট ও ডাউনলোড ফোল্ডার সিঙ্ক হওয়া ডিরেক্টরির বাইরে রাখুন।

স্ক্রিপ্ট, পরীক্ষা, নথি বা পাবলিক সাইটে বোর্ডের কোনো ডেটা অন্তর্ভুক্ত নেই। [ব্রাউজার স্টোরেজের সীমাবদ্ধতা](local-speedial.md#what-is-private-and-what-is-not) ও [স্থানান্তরের গ্রহণযোগ্যতা যাচাই](browser-migration.md) দেখুন।
