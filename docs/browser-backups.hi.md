ये स्क्रिप्ट **Speed Dial बोर्ड** को सुरक्षित रखती हैं: क्रमबद्ध लिंक, शीर्षक, चित्रों के पूरे बाइट, पंक्तियाँ, स्तंभ, खोलने की वरीयता और भाषा। ये ब्राउज़र का इतिहास, पासवर्ड, एक्सटेंशन या असंबंधित बुकमार्क का बैकअप नहीं लेतीं। ये Chrome या Firefox के आंतरिक डेटाबेस के बजाय ऐप के पोर्टेबल `speedial-local-backup` JSON प्रारूप का उपयोग करती हैं।

ये [speeddial.alvit.here.now](https://speeddial.alvit.here.now/) के ब्राउज़र में स्थानीय रूप से चलने वाले ऐप पर काम करती हैं। ये Node.js, Docker या k3s परिनियोजन के [सर्वर बैकअप](../wiki/Operations.md#backup-and-restore) का विकल्प नहीं हैं। सर्वर का पुराना JSON निर्यात ब्राउज़र के पूर्ण बैकअप के रूप में स्वीकार नहीं होता; उस बोर्ड को स्थानांतरित करने के लिए [चित्र संग्रह और रूपांतरण प्रक्रिया](browser-migration.md) आवश्यक है।

यदि आपका बोर्ड अभी भी पुराने `speedial.alvit.here.now` पते पर है, तो पहले ठीक उसी पते से निर्यात करें; ये स्क्रिप्ट अब `speeddial.alvit.here.now` खोलती हैं। पहले से खुले पुराने ब्राउज़र टैब के साथ `--no-open` का उपयोग करें, या उसके सहेजे गए निर्यात को स्पष्ट रूप से संग्रहित करें। पुरानी `speedial-local-backup` फ़ाइलें और `speedial-backup-*.json` डाउनलोड नाम अभी भी समर्थित हैं। [पता बदलने के नोट](local-speedial.md#corrected-address-and-existing-backups) देखें।

## आवश्यकताएँ और ब्राउज़र समर्थन

इस Git चेकआउट से Node.js 24+ चलाएँ। अतिरिक्त पैकेज स्थापित करना आवश्यक नहीं है। macOS पर लॉन्चर `/Applications`, `~/Applications` या `/System/Applications` में Chrome, Firefox, Safari, Edge, Brave, Arc, Opera, Vivaldi, Chromium, Orion, Zen, LibreWolf और Waterfox को पहचानता है। यह लॉन्चर का समर्थन है, ऐसा दावा नहीं कि प्रत्येक उल्लिखित ब्राउज़र का परीक्षण किया गया है। ऐप की स्वचालित जाँच Chromium, Firefox और WebKit पर होती है।

```sh
npm run backup:browser -- --list-browsers
```

अन्य macOS ब्राउज़र के लिए `--app /absolute/path/Browser.app` का उपयोग करें। पहले से खुले ब्राउज़र, Codex के अंतर्निहित ब्राउज़र, Windows या Linux के लिए `--no-open` का उपयोग करके साइट स्वयं खोलें। डिबगिंग पोर्ट, एक्सटेंशन, Accessibility अनुमति या प्रोफ़ाइल फ़ाइलों तक सीधे पहुँच की आवश्यकता नहीं है।

```sh
npm run backup:browser -- --no-open
npm run restore:browser -- backups/YOUR-BACKUP.json --no-open
npm run restore:browser -- backups/YOUR-BACKUP.json --app "/Applications/Brave Browser.app"
```

लॉन्च URL मुख्य पते पर निश्चित है। किसी अन्य ओरिजिन के मौजूदा बोर्ड को ठीक उसी ओरिजिन से निर्यात करना होगा; वहाँ काम करते समय `--no-open` उपयोग करें और इच्छित गंतव्य पता स्वयं जाँचें। ब्राउज़र भंडारण रीडायरेक्ट या होस्टनाम बदलने के साथ स्थानांतरित नहीं होता।

**ये संवादात्मक स्क्रिप्ट हैं।** ये ऐप खोलती और स्थानीय फ़ाइलें सँभालती हैं, लेकिन निर्यात पर क्लिक करना, आयात फ़ाइल चुनना और प्रतिस्थापन की पुष्टि करना आपका काम है। किसी ऐप में कई प्रोफ़ाइल हो सकती हैं: इच्छित प्रोफ़ाइल चुनें और [speeddial.alvit.here.now](https://speeddial.alvit.here.now/) का उपयोग करें। नई प्रोफ़ाइल का खाली होना सामान्य है। स्क्रिप्ट प्रमाणित नहीं कर सकती कि डाउनलोड किस प्रोफ़ाइल ने बनाया।

## Chrome का बैकअप लें

```sh
npm run backup:browser -- --browser chrome
```

1. अपनी मौजूदा Chrome प्रोफ़ाइल चुनें, ऊपर दाईं ओर का तीर खोलें और **Export backup** पर क्लिक करें।
2. सुझाए गए `speedial-backup-YYYY-MM-DD.json` नाम से `~/Downloads` में सहेजें। नाम टकराने पर ` (1)` जैसे प्रत्यय समर्थित हैं।
3. स्क्रिप्ट नए, पूर्ण निर्यात की प्रतीक्षा करती है, उसे सत्यापित करती है, `backups/` में कॉपी करती है, कॉपी को फिर पढ़ती है और उसका पथ, संख्याएँ तथा SHA-256 दिखाती है। वह कभी पुराने निर्यात को विकल्प के रूप में नहीं चुनती। एक साथ कई निर्यात आने पर अनुमान लगाने के बजाय त्रुटि होती है।

यदि ब्राउज़र कहीं और डाउनलोड करता है तो `--downloads /absolute/local/folder` उपयोग करें; ब्राउज़र में भी वही फ़ोल्डर चुनें। क्लाउड सिंक निर्देशिकाओं के बाहर स्थानीय फ़ोल्डर चुनें। सामान्य प्रतीक्षा दस मिनट है; `--timeout 1200` इसे बीस मिनट करता है। फ़ाइल बनने से पहले ब्राउज़र के **Save As** संवाद में पुष्टि आवश्यक हो सकती है। नाम बदले हुए या पहले से डाउनलोड किए गए निर्यात के लिए:

```sh
npm run backup:browser -- --file /absolute/local/export.json
```

स्पष्ट फ़ाइल वाला मोड उसी फ़ाइल को संग्रहित करता है; यह ब्राउज़र का वर्तमान डेटा **नहीं** लाता और उसके ताज़ा होने का प्रमाण नहीं देता। मूल डाउनलोड रखे जाते हैं। निगरानी प्रक्रिया द्वारा जुटाए गए निर्यात POSIX पर `0600` मोड तक सीमित किए जाते हैं; स्पष्ट रूप से दी गई इनपुट फ़ाइलें अपरिवर्तित रहती हैं।

## दूसरे ब्राउज़र में पुनर्स्थापित करें

`YOUR-BACKUP.json` की जगह दिखाया गया बैकअप फ़ाइल नाम रखें:

```sh
npm run restore:browser -- backups/YOUR-BACKUP.json --browser firefox
npm run restore:browser -- backups/YOUR-BACKUP.json --browser chrome
npm run restore:browser -- backups/YOUR-BACKUP.json --browser safari
```

पुनर्स्थापन कमांड के लिए संवादात्मक टर्मिनल आवश्यक है और वह एक बार में एक ब्राउज़र/प्रोफ़ाइल का मार्गदर्शन करती है:

1. वह अलग `restore-source` कॉपी को सत्यापित करके सुरक्षित रखती है। गंतव्य प्रोफ़ाइल में वर्तमान बोर्ड निर्यात करें, भले ही वह खाली हो। स्क्रिप्ट उसे `before-restore` के रूप में सहेजती है ताकि उस बोर्ड को वापस पाया जा सके।
2. टर्मिनल में `RESTORE` टाइप करके पुष्टि करें कि निर्यात सही गंतव्य प्रोफ़ाइल से आया था।
3. उसी ब्राउज़र में **Import backup** पर क्लिक करें, दिखायी गई `restore-source` फ़ाइल चुनें, सारांश देखें और फिर **Replace this board** पर क्लिक करें। macOS में फ़ाइल चयन संवाद में **⌘⇧G** दबाएँ और फ़ाइल का पूर्ण पथ पेस्ट करें।
4. Speed Dial दोबारा लोड करें, जाँचें कि चित्र दिखते हैं और फिर निर्यात करें। स्क्रिप्ट इस `after-restore` निर्यात को संग्रहित करती है तथा क्रमबद्ध लिंक, शीर्षक, चित्र बाइट, ग्रिड, खोलने की वरीयता और भाषा की स्रोत से तुलना करती है। दोबारा बने आंतरिक ID और टाइमस्टैम्प अनदेखे किए जाते हैं। बिना भाषा वाले पुराने बैकअप गंतव्य की भाषा नहीं बदलते।

सफलता केवल सामग्री मेल खाने के बाद बतायी जाती है। मेल न खाना या समय समाप्त होना सत्यापित पुनर्स्थापन **नहीं** है। सभी कॉपी रखी जाती हैं; स्वतः रोलबैक नहीं होता। वापस जाने के लिए सहेजी गई `before-restore` फ़ाइल के साथ कमांड दोहराएँ। निर्यात का मेल सामग्री की समानता सिद्ध करता है; प्रोफ़ाइल, ओरिजिन और दिखाई देने वाले चित्रों की जाँच फिर भी आवश्यक है।

बाद में Chrome पर लौटने के लिए उसी पुनर्स्थापन कमांड में `--browser chrome` और इच्छित सहेजी हुई JSON फ़ाइल उपयोग करें। प्रारूप स्रोत ब्राउज़र पर निर्भर नहीं है। हर पुनर्स्थापन गंतव्य के एक बोर्ड को बदलता है, उसके लिंक मिलाता नहीं है; यदि दोनों संस्करण चाहिए हो सकते हैं तो स्वतः सुरक्षित की गई गंतव्य कॉपी रखें।

जब कोई कमांड प्रतीक्षा कर रही हो तो दूसरे टैब या प्रोफ़ाइल से निर्यात न करें। अलग ब्राउज़र के लिए अलग कमांड चलाएँ। यह एक बार का स्थानांतरण है; बाद के बदलाव सिंक नहीं होते।

## केवल स्थानीय भंडारण और सत्यापन

स्क्रिप्ट का सारा आउटपुट इस चेकआउट की निश्चित `backups/` निर्देशिका में जाता है। कमांड जाँचती है कि Git इसे अनदेखा करता है और इसमें कोई ट्रैक की गई फ़ाइल नहीं है। सिमलिंक वाली आउटपुट निर्देशिका अस्वीकार की जाती है। प्रत्येक बैकअप का नाम अनूठा होता है, दूसरी फ़ाइल पर लिखे बिना दर्ज होता है, फिर पढ़ा जाता है और उसके साथ संख्याओं व डाइजेस्ट वाली `.receipt.json` होती है, जिसमें शीर्षक या URL नहीं होते। अमान्य इनपुट से बैकअप नहीं बनता। CLI ऐप के स्कीमा, base64 और रास्टर हेडर सत्यापन का पुनः उपयोग करती है; गंतव्य ऐप अपने परमाण्विक आयात से पहले चित्रों को डिकोड भी करता है।

पुनर्स्थापन के लिए बोर्ड की `.json` फ़ाइल उपयोग करें, उसकी साथ वाली `.receipt.json` नहीं। रसीद सत्यापन मेटाडेटा दर्ज करती है और बोर्ड पुनर्स्थापित नहीं कर सकती। स्क्रिप्ट पुराने बैकअप या मूल डाउनलोड स्वतः नहीं हटातीं; आवश्यक कॉपी रखें और उनके भंडारण को स्थानीय रूप से सँभालें।

macOS/Linux पर निर्देशिका का मोड `0700` और फ़ाइलों का `0600` है। Windows पर खाते के फ़ाइलसिस्टम ACL से पहुँच सीमित करें; POSIX मोड ACL की गारंटी नहीं हैं। JSON बैकअप सादा पाठ हैं। स्क्रिप्ट में अपलोड या सिंक का कोड नहीं है। फ़ोल्डर Git, Docker बिल्ड इनपुट और सार्वजनिक फ्रंटएंड की अनुमति सूची से बाहर है। `.gitignore` ज़बरन Git में जोड़ने, हाथ से साझा करने, OS बैकअप या स्वतंत्र रूप से कॉन्फ़िगर किए गए सिंक क्लाइंट को नहीं रोकता। केवल स्थानीय भंडारण के लिए चेकआउट और डाउनलोड फ़ोल्डर सिंक की गई निर्देशिकाओं से बाहर रखें।

स्क्रिप्ट, परीक्षण, दस्तावेज़ या सार्वजनिक साइट में किसी बोर्ड का डेटा शामिल नहीं है। [ब्राउज़र भंडारण की सीमाएँ](local-speedial.md#what-is-private-and-what-is-not) और [माइग्रेशन की स्वीकृति जाँच](browser-migration.md) देखें।
